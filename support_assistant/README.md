# Module 3 — Support Assistant

## Overview
A complete RAG-based customer support assistant grounded in Zepto's 8 policy documents.
Uses LangGraph for orchestration, ChromaDB for vector storage, `all-MiniLM-L6-v2` for
local embeddings, and FastAPI for the REST interface.

**MOCK_LLM (default/unset = `1`)**: Fully deterministic, no API key, no network call to any
LLM provider. This is the graded baseline. Set `MOCK_LLM=0` for the optional real-LLM path.

## Files
| File | Purpose |
|------|---------|
| `docs/doc_01.txt … doc_08.txt` | Zepto policy corpus (8 documents) |
| `prompt_template.py` | Structured prompt (role/context/task/format/length + negative constraint + few-shot) |
| `ingest.py` | Load docs → chunk → embed with all-MiniLM-L6-v2 → store in ChromaDB |
| `graph.py` | LangGraph StateGraph: classify_intent → retrieve_and_answer / direct_answer |
| `main.py` | FastAPI app with POST /ask endpoint |
| `Dockerfile` | Locally buildable container (graded baseline) |
| `chroma_db/` | ChromaDB persistent storage (generated by ingest.py) |

## How to Run

### 1. Ingest documents (run once)
```bash
cd support_assistant
python ingest.py
```

### 2. Start the API server
```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

### 3. Test example calls
```bash
# Policy question (triggers retrieval)
curl -X POST http://localhost:8000/ask \
     -H "Content-Type: application/json" \
     -d "{\"query\": \"What is the delivery fee for orders below INR 149?\"}"

# General question (no retrieval)
curl -X POST http://localhost:8000/ask \
     -H "Content-Type: application/json" \
     -d "{\"query\": \"What is the weather today?\"}"
```

### Docker (locally buildable — graded baseline)
```bash
docker build -t zepto-support-assistant .
docker run -p 7860:7860 zepto-support-assistant
# Test at http://localhost:7860/ask
```

## RAG Pipeline Architecture

```
User Query
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  FastAPI  (main.py)  POST /ask                      │
│  Accepts: {"query": str}                            │
│  Returns: {"answer", "sources", "confidence"}       │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  LangGraph StateGraph  (graph.py)                   │
│                                                     │
│  State: {query, intent, retrieved_chunks, response} │
│                                                     │
│  Node 1: classify_intent                            │
│    MOCK: keyword heuristic (no LLM)                 │
│    REAL: LLM classification (MOCK_LLM=0)            │
│         ↓ policy_question          ↓ general_question│
│                                                     │
│  Node 2: retrieve_and_answer    Node 3: direct_answer│
│    Embed query (real, both modes)  MOCK: fixed string│
│    ChromaDB top-3 retrieval        REAL: direct LLM  │
│    MOCK: canned template answer                     │
│    REAL: LLM grounded in chunks                     │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  Pydantic Validation  (ZeptoResponse)               │
│  answer: str | sources: list[str] | confidence: float│
└─────────────────────────────────────────────────────┘
```

### Stage-by-stage breakdown:

**Ingestion** (`ingest.py`): Reads 8 `.txt` files from `docs/`. Each document is treated as
one chunk (per-document chunking — appropriate given each doc is 200–400 chars). Embedded
with `all-MiniLM-L6-v2` (sentence-transformers) running locally. Stored in ChromaDB
collection `zepto_policies` with cosine similarity metric.

**Embedding** (`ingest.py`, `graph.py`): `SentenceTransformer('all-MiniLM-L6-v2')` — runs
entirely on local CPU, no API key, no network call after the initial model download (~90MB).

**Retrieval** (`graph.py` → `retrieve_and_answer` node): Query is embedded with the same model.
ChromaDB `.query()` returns top-3 chunks by cosine similarity. This step runs identically
in both mock and real-LLM modes — ChromaDB requires no API key.

**Generation** (`graph.py`):
- **Mock mode** (MOCK_LLM=1, graded baseline): canned answer from top chunk snippet
  (`f"Based on the retrieved context: {top_chunk[:200]}"`) — no LLM call, fully deterministic.
- **Real-LLM mode** (MOCK_LLM=0, optional): calls Groq API with the structured prompt
  from `prompt_template.py`; retries up to 2 times on JSON validation failure.

**MOCK_LLM toggle**: branches the answer-generation step inside `retrieve_and_answer` and
`direct_answer` nodes. The routing logic (`classify_intent`) is deterministic in both modes.

### Prompt Template Structure (used by MOCK_LLM=0 path)
Located in `prompt_template.py`, following the 5-component skeleton:
1. **Role**: "You are Zara, Zepto's intelligent customer support assistant."
2. **Context**: Retrieved policy excerpts injected into user prompt
3. **Task**: Answer using only the provided context
4. **Format**: JSON `{answer, sources, confidence}`
5. **Length**: 2–4 sentences
- **Negative constraint**: "Do NOT answer using information not present in the provided context."
- **Few-shot examples**: 2 worked examples (delivery fee, opened shampoo return)
